# ADR: 機能駆動のディレクトリ構成（コロケーション）の採用

## 1. 背景
* Next.js (App Router) を採用している
* App Routerは、ルーティングに関係のないファイル（コンポーネント、テスト、APIなど）も同一ディレクトリに配置可能
* 開発スピードを維持しつつ、将来の拡張や変更に強いディレクトリ構成方針が必要

## 2. 決定事項
* `src/app/` 配下の各ディレクトリを「機能単位のモジュール」とする
* 特定の画面や機能に依存するファイルは、すべてそのディレクトリ内に近接配置（コロケーション）する

例（メタデータ機能の場合）:
```text
src/app/metadata/
 ├ page.tsx        (Next.js ページ)
 ├ layout.tsx      (レイアウト)
 ├ api.ts          (API通信ロジック)
 ├ api.test.ts     (APIのテスト)
 ├ components/     (専用UIコンポーネント)
 └ types.ts        (専用の型定義)
```
* ※ 複数機能から呼ばれる汎用コンポーネントのみ `src/components/` に配置する

## 3. 理由
* 変更が容易
  * 修正時、複数のディレクトリを行き来する必要がなく、1つのディレクトリ内で作業が完結する
* 削除や切り出しが容易
  * 機能が不要になったり別プロジェクトへ移植する際、ディレクトリごと削除やコピーするだけで済む
* 認知負荷の低下
  * 「このファイルはどこから使われているか」を心配せず開発できる

## 4. 結果と影響
* メリット
  * プロトタイプ段階での機能の追加や破棄が高速に行える
  * 機能ごとの見通しが良い
* デメリット
  * 複数機能で同じロジックが必要になった際、汎用ディレクトリへ移動（リファクタリング）する手間が発生する
  * （プロトタイプ段階では「必要になってから共通化する」方針とし、これを許容する）
