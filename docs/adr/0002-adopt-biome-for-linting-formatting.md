# ADR: コードのチェック・整形ツールに Biome を採用

## 1. 背景
* 複数人開発では、コードの書き方統一と自動エラー検知（Linter/Formatter）が必須
* 従来のESLint + Prettier構成には以下の課題がある
  * 2つのツールを連携させる設定が複雑
  * コード量増加による処理速度の低下
* プロトタイプ開発のため、設定の手間を省き、高速に開発できるツールが必要

## 2. 決定事項
* ESLintとPrettierの代わりに、統合ツールである Biome を採用する

## 3. 理由
* 処理速度が速い
  * 従来のツールと比較して非常に高速
  * ファイル保存時の待ち時間がなくなり開発が快適になる
* 設定が簡単
  * ツール統合により、ルールの衝突が起きない
  * 設定ファイルが1つで済むため環境構築が容易
* プロトタイプ開発に最適
  * 初期状態で標準的な設定が適用されるため設定の手間が不要

## 4. 結果と影響
* メリット
  * 設定がシンプルになる
  * コード整形とエラー検知が一瞬で終わり、開発に集中できる
* デメリット
  * Next.js特有のチェックなど、ESLintの拡張機能が一部使えない
  * （プロトタイプ段階では一般的な構文チェックで十分とし、許容する）
